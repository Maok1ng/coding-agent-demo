# 编码闭环：本版不实施大型 Workflow 引擎

这份文档保留为架构取舍说明，替代旧的阶段状态机草案。
当前重构不增加 WorkflowDefinition、WorkflowRun、阶段 registry、阶段跳转 DSL 或通用 validator 平台。
不要把这些旧设想当成需要补齐的功能。

## 采用轻量编码约定

```text
阅读相关代码和项目约定 → 确定范围 → 最小修改
    → 运行相关检查 → 根据失败修复 → 核对 diff 并交付
```

这是面向编码任务的行为约定，不是每条消息必须经过的固定流水线。
纯解释不应创建修改任务；需求不明确时先提问；简单修复不必先启动所有专业角色。
测试、构建、静态检查按项目实际情况选择，不能虚构“测试通过”，不能把未运行检查当成成功。

## 各机制只做自己的事

| 机制 | 职责 |
| --- | --- |
| Application | 真实用户输入、会话、Goal / Plan 和 Turn 生命周期 |
| Orchestrator | 理解请求，按需分配 Codebase / Planning / Implementation / Review / Research |
| AgentRunner | 所有角色共用的模型和工具循环；串行调用，子角色不递归委派 |
| ToolRuntime | 参数与权限校验、执行、完整结果落盘和证据事件 |
| Todo | 当前会话的轻量清单，不是验收证明或共享任务板 |
| Goal | 显式长期目标及主任务验收，不强制普通请求续跑 |
| Plan | 全任务只读边界，只有真实用户能确认当前方案的执行 |
| Hook | 内部扩展和观察，不能代替核心权限与持久化 |

当前读取用户级和工作区根目录 `AGENTS.md`，按需加载 Skills 和相关长期记忆。
记忆由 Application 的回合生命周期管理，不借 Stop Hook 绕过权限，不增加新的 Agent 循环。
不增加向量检索、多供应商路由、Web 界面或云端调度。

## 最小证据与恢复边界

- 内容搜索返回文件、行号和附近代码；按行读取避免无差别加载整个文件。
- 编辑保留唯一匹配保护和并发修改检测，交付前核对实际 diff。
- Shell 输出、退出码、取消/超时状态和工具结果引用保存；Review 不运行任意 Shell。
- 后台进程属于当前 Turn，必须等待真实结果才能用于验证；Turn 结束、中断和退出都会清理。
- 子角色提交摘要和证据引用，不把全部历史反复复制进主会话。
- 恢复只加载历史，不自动重放写入、不恢复进程、不沿用批准；修改后重新检查实际状态。

旧 Cron、常驻 Team、邮箱、共享任务板和专用 worktree 调度从产品执行路径移除。
用户已有历史、文件、分支和 worktree 不删除，旧工具记录不重放。

## 以后何时再考虑阶段控制器

只有出现明确且重复的强制流程需求，例如必须审批后部署，才单独设计阶段、授权和证据规则。
届时需要独立评审，不从现有 Todo 或 Goal 状态隐式推导流程阶段。
本次验收只覆盖专用角色、权限、编码工具、真实结果和安全恢复，不把大型 Workflow 作为隐藏后续任务。
