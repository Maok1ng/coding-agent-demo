# 最终检查记录

宿主在回合收尾后整理文件修改和命令事实，显示实际退出码、超时、取消及代码版本情况。
报告不读取模型说“完成了”或“测试通过了”的文字来决定状态，也不为生成报告再执行命令。

## 报告中的两类事实

- **执行结果**：正常结束且退出码为 `0` 才显示“执行成功”。超时、取消、仍在运行、清理未确认优先于退出码；不能因为记录中恰好有 `0` 就显示成功。
- **代码版本**：命令开始时保存已经读取/修改文件的摘要，最终整理时重新核对这些文件。版本不符、文件删除、或本轮新增的修改没有进入旧快照时，旧命令标记为过期。缺少快照、文件不可读取、或核对预算耗尽则标记为未核实。

如果宿主记录了命令结束时的摘要，也会检查命令执行期间是否改动了已跟踪代码。即使之后又恢复旧内容，也不会把这条已知发生改动的检查当作稳定版本验证。

后台命令可能多次调用 `process_status`、`wait_process`，随后又在回合结束时保存一次；报告按进程 ID 合并，保留最终状态和最初的代码快照。前台命令使用独立 ID，不按命令文本合并。命令先后按宿主登记的启动顺序计算，后台较晚结束不会被误认成较晚启动的重跑。

失败后的修复重跑保留两次事实。若**完全相同的命令**最后一次在当前代码版本上执行成功，先前的普通失败或超时标记为“先前失败，后续同命令已重跑”，不再阻止最终汇总；旧退出码和失败次数仍然保留。最新结果对应旧代码、缺少可核实快照，或只是另一个命令成功，都不能解除旧失败。取消、仍在运行和清理异常也不能靠重跑掩盖。

## 汇总状态

| 状态 | 含义 |
|---|---|
| `not_run` | 没有实际命令记录；若修改了文件，会明确显示尚未验证 |
| `failed` | 存在尚未由同命令在当前版本上成功重跑解除的失败或超时 |
| `incomplete` | 存在取消、运行中或清理未确认的命令 |
| `stale` | 没有对应当前代码的检查，已有检查对应旧版本 |
| `recorded` | 已整理执行事实；应结合每条命令的版本标记判断适用范围 |

`recorded` 不是“测试全部通过”。`pwd`、编译、测试等都可能返回退出码 `0`；宿主只能证明记录中的命令如何结束，不能由此证明它运行了测试、覆盖了全部需求或得到正确实现。

## 上限与边界

- 摘要显示最后 20 条命令和省略数量，但汇总状态仍纳入被省略的未解除失败/未完成记录，并显示历史失败和已恢复数量。完整事实保存在原运行记录中。
- 最多核对 200 个已登记路径、总计 16 MiB，每个文件不超过项目已有的 2 MiB 限制。预算外路径保持未核实。
- 核对逐层拒绝符号链接，只读取普通文件；不会等待 FIFO，不把正文复制进报告，不恢复编辑版本或权限。
- 只跟踪本轮已读取、修改及命令快照登记的文件，不扫描整个仓库。任意 Shell 对未跟踪文件、远端资源的影响不在这份版本证明内。
- 前台与后台命令通过同一个 `capture_source_versions` 在结束边界再次保存摘要。核对是有界的乐观摘要检查，不是操作系统沙箱或跨程序文件锁；无法证明两次快照之间所有短暂改动都没有发生。
- 没有文件修改、也没有命令执行的普通解释不额外显示空报告。报告不自动创建 Goal，不强迫普通任务进入新的验收循环。
