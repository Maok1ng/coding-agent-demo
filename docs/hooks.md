# Hook 与执行内核的分工

Hook 是执行经过某个边界时调用的进程内 Python 扩展，不是完整工作流，也不是权限的唯一入口。
本项目不兼容其他产品的 Hook 配置协议，不自动安装或执行目标仓库中的脚本。

## 权限不能放在可选 Hook 中

工具调用统一进入 ToolRuntime：

```text
参数校验 → 运行模式、角色与宿主权限检查 → 必要的用户确认
    → PreToolUse → 执行 → PostToolUse → 保存结果和证据
```

隐藏工具只减少误调用，不能代替执行时检查。即使没有任何 Hook，
非 Implementation 角色也不能写入、运行 Shell 或调用未分类的 MCP 工具；Plan 同样不能绕过。
PreToolUse 可以进一步阻止操作，不能反过来批准内核已经拒绝的调用。
PostToolUse 发生时操作已经执行，不能用于撤销或阻止刚才的写入。

## 保留的扩展点

| 事件 | 用途 | 边界 |
| --- | --- | --- |
| `UserPromptSubmit` | 输入边界的日志或上下文扩展 | 不替代真实用户授权，不扫描历史制造批准 |
| `PreToolUse` | 额外约束、执行前观察 | 不跳过内核校验，不自行扩权 |
| `PostToolUse` | 观察结果、输出大小等 | 被调用不代表工具成功；后台启动不代表测试通过 |
| `Stop` | 回合结束边界的扩展或记录 | 子角色结束不代表主 Goal 完成 |

现有回调按注册顺序执行，首个非 `None` 返回值结束该次分发。
这是轻量内部接口，没有 matcher、外部脚本运行器、超时隔离或通用结构化决策合并。
不要让多个回调依赖彼此的副作用，也不要把日志是否输出当作执行是否成功。

## 核心职责不依赖扩展

- Application 处理会话、真实用户输入、Goal 与 Plan 路由。
- AgentRunner 处理模型循环、工具结果配对、压缩、取消和角色结果。
- ToolRuntime 处理权限、实际执行和证据；Environment 处理 Shell 进程及 Docker。
- Goal 验收由主任务控制，不能由子角色的 Stop 误触发；验收反馈不能增加权限。
- 中断和恢复都不沿用旧 Plan 批准，不重放工具，不恢复进程。

本版不扩建 Hook 协议，也不通过 Hook 强制大型多阶段状态机。
代码阅读、修改、检查、修复、交付是轻量编码约定；完整边界见 `workflow-design.md`。
