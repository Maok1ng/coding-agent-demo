# 规则、长期记忆与上下文压缩

本版迁移 s09 的“文件 + 短索引 + 相关性选择 + 按需正文 + 提取 + 整理”思想，
保留 s08 的四步压缩。不是把教学脚本的全局变量或另一套 Agent Loop 复制进工程。

## 三种机制不混用

| 机制 | 保存什么 | 生效范围 |
| --- | --- | --- |
| 短规则 | 人维护的工作方式、项目约定 | 每次模型请求前读取 |
| 长期记忆 | 以后仍有用的偏好、反馈、稳定事实和线索 | 跨会话，按相关性选择 |
| Session / Compact | 当前工作的历史与状态 / 历史压缩 | 当前会话，不自动转为长期规则 |

用户规则默认是 `~/.coding-agent/AGENTS.md`，项目规则是工作区根目录 `AGENTS.md`。
同一任务中，具体项目约定优先于通用用户默认值，当前真实用户要求优先；权限始终由宿主决定。
用户规则最多 8,000 字符，项目规则最多 24,000 字符；超长截断。只读取两个显式根目录，不扫描父目录或嵌套规则。
用户规则目录可由 `--memory-home`、`AGENT_MEMORY_HOME` 或宿主模型配置 `memory_home` 指定，优先级依此排列。
不自动创建或改写规则文件，也不把学习到的每条经验塞进规则。

## 存储

```text
~/.coding-agent/
  AGENTS.md                    用户维护的通用规则，可选
  memory/
    MEMORY.md                  可重建目录
    indentation.md             用户个人长期偏好
<workspace>/
  AGENTS.md                    用户维护的项目规则，可选
  .memory/
    MEMORY.md
    test-command.md            项目事实
    .lock                      进程间锁
    .snapshot-<uuid>.json       修改前快照，不参与召回
```

每条正文使用 YAML frontmatter：`name`、`description`、`type`、`updated_at`，下面保存 Markdown 正文。
`user` 类型保存在用户目录；`feedback`、`project`、`reference` 保存于当前项目。
明确写着“本项目”等范围的偏好即使被模型标为 `user`，宿主也降为项目反馈，避免影响其他仓库。
每个存储最多 200 条，每条正文最多 6,000 字符。默认代码搜索排除 `.memory/`。

MEMORY.md 是供人查看的生成索引。召回目录从真实文件的元信息重新派生，不信任索引中可能被手工改坏的路径。
用户记忆对该用户的各项目可见，项目记忆只读当前显式工作区，不按项目同名目录混用。

## 运行流程

```text
真实用户输入
  → Application 创建 Turn
  → MemoryManager：短目录选择最多 5 条；模型失败则关键词降级
  → 读取所选正文（总计最多 16,000 字符）
  → 放入 RunContext.memory_context，主角色和子角色共享
  → AgentRunner 使用同一份召回背景工作，正常进行工具循环与压缩
  → 顶层回合完整结束，进程清理与会话保存完成
  → 只从本次原始用户输入提取长期候选
  → 宿主校验、去重、写入、重建索引；达到 10 条后尝试整理
```

选择器只收到有界的名称、类型和描述，不收到全部正文。它只返回目录下标，没有工具。
无效 JSON、布尔下标或越界下标触发中英文关键词降级；有效的 `[]` 表示没有相关记录，不强行注入。
记忆以 JSON 数据单独提供，明确不是用户命令、工具批准或执行权限。当前代码和当前要求比旧记忆更可信。
召回保存在 RunContext，不随着 messages 的裁剪消失；每个用户回合重新选择，子角色不再额外召回或提取。

## 提取为什么比课程更保守

教学版从最近对话提取；本工程只把**本次真实用户输入**交给提取器，不把工具输出、角色回复、
压缩摘要、会话恢复通知或助手猜测作为新的用户偏好。它不会从扫描代码的结果自动推断长期事实。
候选必须有合法字段、`scope: persistent`，以及真实输入中逐字存在的 `source_quote`。
临时限制、明显秘密、无效字段和重复正文不会写入。模型识别为纠正的同名事实可以更新；更新前保留快照。
这些检查是保守过滤，不是能够证明语义或识别所有秘密的安全审计；不要把凭据输入或保存为记忆。

Plan、等待用户回答、达到调用上限、取消、主流程异常、资源清理失败时不提取。
完整结束只指本次顶层委派链结束，不要求 Goal 必须完成；但子角色结束本身不会触发提取。
自动学习写的是独立宿主记忆数据，不是代码、Git、远端资源或 AGENTS.md；不向只读角色开放写工具。

默认复用当前模型，也可在宿主配置指定 `memory_model`。有目录时通常增加一次选择请求；
合格回合增加一次提取请求；达到整理阈值可能再增加一次请求。辅助请求计入 Turn 共用调用上限，
选择时为主任务至少保留一次调用。摘要压缩仍沿用现有策略，不因此新增另一套模型循环。
`memory_auto_extract: false` 只关闭提取；`memory_enabled: false` 关闭自动召回和提取。
短规则、会话和显式查看/删除命令仍可使用。

## 写入、并发与恢复

目录与文件使用 no-follow 描述符，不跟随符号链接或命名管道。新目录为 700，新文件为 600。
单文件写入使用唯一临时文件、fsync 和原子替换；合作进程使用 flock 读写锁。
模型调用在锁外进行，写入时比较提取前后的存储签名；另一会话改过内容就放弃本次提交，不覆盖它。
整理先校验完整非空列表、重名、作用域和长度，再留原始文件快照并替换；异常或取消时恢复原文和索引。

这不是数据库级的整目录崩溃事务：断电或强制 kill 发生在多个文件替换之间时，可能需要从
`.snapshot-*.json` 手动恢复。快照保存原始文件名和完整原文，不自动回放，也不作为模型记忆加载。
没有自动清理备份，避免未经用户决定删除可恢复资料；长期使用时需自行管理磁盘与隐私。

```text
/memory list
/memory show user/indentation.md
/memory forget project/test-command.md
```

命令由真实用户输入触发，在宿主直接执行，不调用模型。Plan 可以查看，不能删除。
删除后重建索引，旧正文保留在快照中；不清除聊天历史，也不保证彻底擦除私人信息。
本项目已忽略 `.memory/`，包内容检查也拒绝它；其他目标仓库需要自行加入忽略规则。

## 与 s08 的衔接

现有 ContextCompact 已有：大工具结果转存 → 历史裁剪 → 旧结果缩短与新结果适配 → 必要时模型摘要，
并保留完整归档、当前请求、工具配对和一次 API 超限补救，因此没有另写压缩器。
在这套流程上增加本次角色运行的代码工作集：成功读取时登记当时版本和实际展示片段；
普通压缩、手动摘要及 API 超限补救都按剩余预算保留最近仍有效的片段。
文件已变化、删除或无法安全确认时，只留路径与旧行号范围提示重读，不把旧代码当成当前实现。
每个角色独立维护工作集，子角色不会因此取得父角色的完整代码上下文。

工作集属于当前执行上下文，不是长期记忆；不会写入 `.memory/` 或自动变成项目规则。
旧会话或上一轮留下的工作集仅作未验证线索，不自动读取文件、不回填编辑前置版本或审批。
工作集登记和选择不额外调用模型，既有摘要策略保持不变。具体预算与恢复边界见 [上下文压缩](context-compaction.md)。
压缩不会调用记忆提取，也不把 transcript 当长期知识库；原始用户输入由 Application 单独保留到回合结束。
会话恢复只加载历史、等待真实用户输入，不在恢复时自动召回、提取或启动旧任务。
