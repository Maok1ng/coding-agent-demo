# 重复编辑失败保护

同一回合中，内建 `write_file` / `edit_file` 对同一文件、相同参数、相同真实原因连续失败时：

1. 第 1、2 次保留原始工具错误，由模型根据原因修正。
2. 第 3 次额外给出一次宿主提示：重新读取当前文件，生成不同候选，或者向用户提问。
3. 第 4、5 次仍保留错误，不重复插入相同提示。
4. 第 6 次停止整个当前 Turn；停止标记由主角色和子角色共同遵守，不能换个角色继续重试。

失败的修改不会落盘。提示不是用户授权，也不增加工具权限。每次调用仍经过原有权限、预览、审批、版本检查和结果记录。

停止时会为同批剩余调用补齐“未执行”的工具结果，不再请求模型或派发新角色；此前已成功的修改保留。
未完成 Goal 进入 `blocked`，等待用户决定下一步。新的真实用户消息开启新 Turn，并使用新的失败计数；
普通问题不会恢复旧 Goal，需要 `/goal resume` 或 `/goal edit ...`。用户主动中断仍沿用 `paused` 语义。

## 什么会累计

只有内建文件修改在生成候选或应用候选时发生的确定性失败参与计数，例如匹配不存在/不唯一、未先读取、读取版本过期、文件消失、并发创建或修改、文件类型/编码/大小不符合要求。

参数校验错误、工作区越界、操作系统权限拒绝、用户拒绝、Hook 拒绝/异常、中断、读取失败、Shell 和 MCP 错误不参与计数。文件已经写入后发生的 `PostToolUse` 异常也不算编辑失败；真实修改仍会被登记。

相同文件生成不同候选，或者遇到不同的实际原因，会开始新的失败序列。文件实际写入成功会清理该文件的计数。单纯读取成功不证明旧候选已修正，所以不会清零。不同文件分别计数，交替查询不会清掉已有记录。

## 状态放在哪里

`RunContext.edit_recovery` 是宿主的本轮状态。`for_role()` 保持同一对象，因此所有角色共用；创建新的 Turn 会获得新对象。上下文压缩、工具调用 ID 变化、重新构建角色运行时都不会清空计数。

该状态不加入会话恢复字段，不从历史错误重新推导，也不恢复旧回合的停止标记。模型不能通过工具参数重置计数或撤销停止。

仅保留最近 20 个文件的失败记录，每份候选只保存 SHA-256 指纹与次数，不重复存储大段源码。完整真实错误仍保存在该次工具结果及工具证据文件中；达到第 3/6 次时另附保护状态快照，主循环根据 `ToolOutput.edit_recovery` 和共享的 `stopped` 标记处理回合收尾。
